# 자막 언어팩 — 0.12 알파

> 0.12.2 알파 릴리즈는 [프로필 관리자](PROFILE_MANAGER.ko.md)에 선택 백업 ZIP 복원을 추가하며, 같은 프로필이 있으면 중단합니다. 배포 버전만 바꾸고 0.12.0 카탈로그 바이트·복구 공간은 유지합니다. `multilingual-verification.json`의 기존 해시는 원래 0.12 릴리즈 검증 기록입니다.


**한국어** | [English](MULTILINGUAL.en.md) · [README](../README.md)

번역 JSON을 추가하고 패치 런처에서 자막 언어를 고르는 구조입니다. 게임을 닫은
상태에서 선택한 파일을 준비한 뒤 기존 ‘플레이’ 창을 엽니다. 자막은 계속 게임
화면 안에서 표시됩니다.

기존 `0.11.0-beta.1` 한글·와이드 통합판과 재현 빌드 경로는 그대로 유지됩니다.
이번 추가 기능은 그 통합판이 설치된 **Windows 패키지 x64 2608.3123.1.0**용입니다.

[0.12 알파 추가 기능 다운로드](https://github.com/schultz1138/crimson-skies-korean-wide/releases/tag/v0.12.2-alpha.1)

## 포함된 언어

| 언어팩 | 현재 번역 범위 |
| --- | --- |
| `ko-KR` | 기존 한국어 기본판 |
| `en-US` | 부분 번역 예제: 내장 대사 1개, 튜토리얼 3줄, 영상 1줄, 크레딧 역할 1개, UI 4개 |
| `es-ES` | 내장 대화 하나의 5개 구간 예제 |

영어·스페인어는 개발자가 확장할 예제이며 전체 번역판이 아닙니다. 번역하지 않은
항목은 한국어로 나옵니다. 음성·대사 식별자·타이밍은 유지하며, 런처에서 적용 전에
번역 수와 전체 항목 수를 볼 수 있습니다.

## 사용 방법

1. 기존 통합판이 없다면 [0.11.0 베타 1](https://github.com/schultz1138/crimson-skies-korean-wide/releases/tag/v0.11.0-beta.1)을 먼저 설치합니다.
2. `CrimsonSkies-Multilingual-0.12.2-alpha.1.zip` 전체를 쓰기 가능한 로컬 폴더에
   풉니다. 카탈로그·패치·도구·고지 파일을 함께 두세요.
3. 진행 상황을 저장하고 게임과 기존 ‘플레이’ 창을 모두 닫습니다.
4. `MultilingualLauncher.exe`를 열고 게임 폴더 또는 `Content`를 지정한 뒤
   언어를 고릅니다. **상태 확인**은 파일을 바꾸지 않고 검사합니다.
5. **적용 후 실행**을 누른 뒤 기존 창의 플레이를 누릅니다. 기존 창의 게임 언어는
   활성 언어팩 ID 하나를 표시합니다. 다른 언어로 바꿀 때는 두 프로그램을 닫고
   패치 런처에서 다시 고르세요.

모든 언어팩은 게임의 한국어 리소스 슬롯을 사용합니다. 기존 창의 관리 항목은 선택한
ID를 `-locale ko-KR`로 연결합니다. 게임 내장 영어 로케일을 직접 지정하면 이 번역
리소스를 거치지 않습니다. 해상도·AA·다른 설정은 유지합니다. 저장된 언어 설정이
없으면 기존 창의 기본 선택값으로 연결하며 설정 파일을 임의로 만들지 않습니다.

**0.11 복구**는 콘텐츠 3개와 기존 해상도 메뉴를 검증된 한글·와이드 통합판 상태로
돌립니다. 사용자가 다른 값으로 바꾸지 않은 경우에만 저장된 게임 언어도 선택적으로
복원합니다. 0.11 자체 제거는 기존 통합 설치기와 그 설치기의 백업으로 진행하세요.
저장 데이터는 읽거나 변경하지 않습니다.

백업·복구 기록은 게임 경로와 버전별로
`%LOCALAPPDATA%\CrimsonSkiesSubtitlePacks\Backups`에 보관됩니다. 복구가 필요할
동안 유지하세요. 출처를 모르는 혼합 파일은 덮어쓰지 않습니다. 전환 중 중단됐다면
게임과 플레이 창을 닫고 다시 실행하세요. 네 파일의 복구본을 모두 검증한 뒤 전환
직전의 일관된 상태로 돌아갑니다.

언어 추가 등으로 카탈로그가 달라진 새 빌드를 사용할 때는 먼저 이전 패키지의
**0.11 복구**를 실행하세요. 복구가 끝날 때까지 이전 패키지와 백업을 보관합니다.
복구 기록은 카탈로그별로 분리되며 새 카탈로그가 이전 활성 언어팩을 복구하지는 않습니다.

## 소스에서 빌드

[기존 재현 안내](REPRODUCING.ko.md)에 따라 원본 게임 사본, 고정 Python 환경과
의존물을 준비합니다. 설치된 패치 게임을 빌드 입력으로 사용하지 마세요.
저장소 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe multilingual\build.py `
  --input-content D:\CrimsonSkies-original\Content `
  --dependencies .deps `
  --out D:\CrimsonSkies-multilingual-001
```

출력은 소스·의존물·원본 게임과 분리된 새 경로여야 합니다. 먼저 0.11 기본판을
소스에서 재생성하고, 언어팩을 자동 검색해 글꼴·데이터·내장 자막 데이터를 생성한 뒤
새 차분을 인코딩·복원 검증하고 카탈로그에 고정된 런처를 컴파일합니다. 기존 공개
차분이나 완성된 게임 DLL을 재생성 입력으로 사용하지 않습니다.

| `--out` 아래 경로 | 용도 |
| --- | --- |
| `CrimsonSkies-Multilingual-0.12.2-alpha.1.zip` | 배포 가능한 추가 기능 |
| `bundle/CrimsonSkies-Multilingual-0.12.2-alpha.1/` | 동일한 배포 파일 폴더 |
| `build-report.json` | 빌드 결과와 파일 해시; 개인 절대 경로가 포함될 수 있음 |
| `work/` | 원본에 의존하는 전체 게임 파일·문맥·중간 파일·로그; 비공개 유지 |

배포에는 완성 ZIP을 사용하세요. `work/`는 공개하지 않습니다. ZIP에는 차분·직접
작성한 런처·고정 xdelta 도구·항목 수 보고서·라이선스만 포함됩니다.
`--skip-launcher`는 비공개 준비 폴더만 만들며 배포 ZIP을 생성하지 않습니다.
`--pack-root`로 다른 소스 언어팩 폴더를 지정할 수도 있습니다.

런처 소스만 수정했다면 `--package-from D:\이전-비공개-전체빌드 --repo-root .
--out D:\새-배포본`으로 기존 비공개 빌드를 검증해 재사용할 수 있습니다. 기본판·
모든 언어 파일·카탈로그·차분 복원을 다시 확인한 뒤 컴파일합니다. 공개 ZIP이나
차분만 있는 폴더는 거부합니다. 이 모드로 번역·카탈로그를 바꿀 수는 없으며 새 언어와
번역 수정은 위의 원본 입력 전체 빌드를 사용합니다.

컴파일러의 타임스탬프·모듈 MVID·컴파일러가 만든 비공개 타입 GUID만 소스·카탈로그
기준으로 고정하고 IL·다른 메타데이터는 유지합니다. 독립된 두 번의 최종 컴파일과
배포 묶음 생성에서 런처와 ZIP이 같았습니다. 세부 생성 경로는 아래 검증 기록에 있습니다.

## 새 언어 추가

1. [영어 예제](../multilingual/packs/locales/en-US/locale.json)와 번역 파일을
   `multilingual/packs/locales` 아래 새 폴더로 복사합니다.
2. 고유한 언어 ID와 표시 이름을 지정합니다. `base: "ko-KR"`, 고정 글꼴 소스를
   유지하고 모든 항목을 번역하기 전까지 `status: "partial"`을 사용합니다.
3. JSON 번역을 작성합니다. 내장 대사 키는
   `pipeline/assets/localization/native_captions.json`에서 확인합니다. 튜토리얼·
   영상·크레딧·UI 키는 언어팩 빌드가 만든 비공개 문맥 카탈로그에서 확인하세요.
   원본에 의존하는 문맥 카탈로그는 공개 소스에 넣지 않습니다.
4. `multilingual/build.py`를 다시 실행하면 새 언어와 런처 선택지가 자동으로
   생성됩니다. 일반적인 번역 추가에는 C# 목록이나 내장 코드를 고칠 필요가 없습니다.
5. 번역률·글리프·줄 길이를 확인하고 실제 게임에서 시험합니다. 번역 JSON과 실제
   확인한 장면 기록을 함께 PR로 보내주세요.

번역 파일은 `schema`, `nativeCaptions`, `strings`로 구성됩니다. 빠진 항목은
한국어로 대체하고, 중복·알 수 없는 키는 오류로 처리합니다. 언어팩 메타데이터는
명령을 실행하거나 임의 DLL·글꼴 다운로드를 지정할 수 없습니다.
[언어팩 형식 안내](../multilingual/packs/README.md)와 JSON 스키마에 세부 규칙과
단일 언어팩 빌드 예제가 있습니다.

현재는 고정 Noto BASIC 렌더러의 NFC BMP·왼쪽에서 오른쪽으로 쓰는 문자를 지원합니다.
아랍어·인도계 문자 조형, RTL, 이모지는 추가 구현이 필요합니다. 무전·영상·크레딧
글꼴은 소스에서 생성하지만 UI 번역은 게임의 기존 한국어 UI 글꼴 네 개에 공통으로
있는 글자 범위 안에서만 허용합니다. 무전 글꼴에 글자를 추가해도 기존 UI 글꼴까지
늘어나지 않습니다. 미지원 글자·너무 긴 줄·형식 토큰 변경은 빌드를 중단합니다.

## 구현과 검증 범위

`multilingual/packs/`는 번역을 검증·병합하고 글꼴·데이터를 재생성합니다.
`multilingual/runtime/native_variant.py`는 기존 분기·실행 코드·언와인드 정보를
유지하면서 필요한 읽기 전용 언어 데이터를 추가합니다. `multilingual/launcher/`는
Native·Data0000·Data0005·기존 창 JSON 네 파일과 언어 설정을 복구 가능한 순서로
전환합니다. 별도 자막 창이나 상주 감시 프로그램은 없습니다.

자동화된 내장 코드 실행·데이터 검사·설치 복구 검증은 실제 엔딩까지 플레이했다는
뜻이 아닙니다. 기존 0.11 전체 플레이 검증과 예제 언어의 실제 글꼴·배치 확인은 남아
있습니다. 소스에 연결된 자동 검사와 실제 플레이 상태는
[검증 기록](multilingual-verification.json)에 구분합니다.

직접 작성한 코드·번역은 저장소 MIT 라이선스를 따르며 게임 원본의 권리는 별개입니다.
재배포할 때 글꼴·xdelta·의존물 고지를 유지하고 기여할 권리가 있는 번역만 추가하세요.
