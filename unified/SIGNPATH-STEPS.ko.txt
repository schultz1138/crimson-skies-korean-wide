4. 신청 설명
같은 폴더의 SIGNPATH-APPLICATION.txt에서 영어 신청 본문을 사용한다.
'DRAFT' 안내와 연락처 자리표시는 실제 제출 내용에 넣지 않는다.
반드시 밝힐 사항:
- 신규 개인 팬 패치이고 게임 원본은 사용자가 별도로 소유해야 한다.
- 최종 게임 패키지는 게임 기반 차분/번역 자산을 포함한다. 이 사용 사례의 적합성도 문의한다.
- 서명에 제출하는 artifact는 직접 작성한 C# 설치기 EXE만 포함한다.
- xdelta3.exe는 제3자 원본 도구여서 이 프로젝트 명의의 서명을 신청하지 않는다.
- xdelta 버전 조회가 성공한 사실과 실제 패치/플레이가 아직 미검증인 사실을 구분한다.
- 기존 게임 원본, 음성/글꼴/차분, 세이브, 계정 데이터는 서명 artifact에 포함하지 않는다.

5. 직접 제출 및 회신 확인
입력 내용을 검토한 뒤 본인이 제출한다. 추가 질문이 오면 그 질문에 맞춰 답한다.
개인 팬 패치/게임 기반 차분 데이터의 적합성, 신규 프로젝트의 승인 여부는 심사 결정이다.

6. 승인 안내를 받은 뒤 본인이 할 일
- SignPath 계정 로그인/이메일 확인/MFA 설정.
- 안내에 따른 SignPath GitHub App 연결 승인(가능하면 이 저장소만 선택).
- GitHub Settings > Environments에서 code-signing 환경을 준비하고 수동 승인자를 지정.
- SIGNPATH_API_TOKEN은 환경 Secret에 직접 저장하며 채팅/소스에 넣지 않는다.
- 안내받은 조직/프로젝트/정책/artifact 식별자를 환경 Variables에 저장:
  SIGNPATH_ORGANIZATION_ID, SIGNPATH_PROJECT_SLUG, SIGNPATH_POLICY_SLUG, SIGNPATH_ARTIFACT_SLUG
- 설치기 전용 artifact 설정은 unified/signpath-installer.xml을 담당자와 확인한다.
- main의 Windows release readiness를 수동 실행하고 request_signing을 선택한다.
- SignPath의 서명 요청도 본인이 수동 승인한다.

7. 서명 후 검증
서명된 설치기를 원래 준비 폴더에 넣고 release.py finalize의
--require-installer-signature 경로로 패키징한다.
SAC가 활성화된 별도 검증 환경에서 설치기 실행 → 실제 xdelta 패치 작업 → 게임 실행 →
비교 촬영 → 원복/해시 검증을 이어간다. 서명 발급만으로 이 검증이 끝나는 것은 아니다.
